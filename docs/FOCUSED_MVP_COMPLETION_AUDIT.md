## Approved completion decisions

1. `1A` — The Electron process starts the Renderer only. The sidecar, database, Codex process, and account-status reads
   begin only after the adult confirmation IPC succeeds. Other host IPC fails closed beforehand. A failed initialization
   is retryable from the confirmation screen, and acknowledgement is not persisted across application launches.
2. `2A` — The medical, legal, and financial statement is a scope acknowledgement, not a keyword classifier or technical
   rejection rule. Free-topic input remains general and is persisted unchanged after acknowledgement.
3. `3A` — Revising an already-active objective is allowed. Reactivating an invalidated objective counts against the
   five-active limit and is rejected when five or more objectives are active. Legacy over-limit data is retained and
   readable; creation and reactivation stay blocked until the active count falls below five.
4. `4A` — Selecting project B immediately updates the visible shell to B and clears all A-owned workspace content.
   Workspace actions remain disabled until B is loaded. Source evidence and attainment evidence have independent loading,
   empty, and error regions. Late A responses cannot populate B.

Rejected alternative `4B`: retaining A until every B request completes would make the slowest request control the whole
screen and would require simultaneous “selected” and “displayed” project ownership. That dual state leaves A actions
available after the learner has expressed intent to work in B, increasing stale-data and wrong-project operation risk.

## Installed regression verification baseline

- **Target:** replace the installed DMG that rejected a valid Codex App Server and every project-creation request.
- **Responsibility boundary:** Codex initialization validates the provider-reported version; the setup form maps learner
  text into the Core's closed `constraints` contract; the Core remains the final validation and persistence authority.
- **Expected observable behavior:** after adult confirmation, a missing CLI shows installation guidance; an unauthenticated
  external CLI shows the device-login command and refresh action; submitting a complete free-topic form opens the created project; relaunch
  returns the same project from SQLite.
- **Unchanged assumptions:** Codex remains pinned to `0.144.5`, credentials remain external-CLI-owned, learner text remains
  unchanged apart from whitespace trimming, and no external telemetry, Web retrieval, or learner-code execution is added.
- **Previous installed verification:** the prior bundled build created `UI回帰確認` and restored it from SQLite after
  restart. That evidence remains valid for local persistence but is superseded for runtime/authentication acceptance.
- **Completed account boundary:** the already authenticated external CLI was detected, a real first AI reply completed,
  LearnStepper was restarted, and both the saved conversation and authenticated availability were reused without exposing
  account identity, login URLs, tokens, or learner-sensitive content.
- **Completed option-A sequence:** the final DMG was verified, mounted, and launched against external Codex CLI 0.144.5;
  a fresh disposable project was created through the actual complete form, a real AI response completed, the app was
  stopped and relaunched with the same profile, the saved thread resumed and reconciled, and a second real AI response
  completed. The run also confirmed the Library location/upload-unavailable notice and external authentication reuse.
- **Evidence dimensions:** the legacy filename `option-a-adult-eligibility-1440x960.png` records the requested outer
  Electron window size; its captured page viewport is 1440×928. Current acceptance links use captures whose dimensions
  match their filenames where the distinction matters.
- **Artifact source of truth:** `release/LearnStepper-mac-arm64.dmg` and its `.sha256` file are authoritative. Any loose
  intermediate directory under `release/mac-arm64/` is build scratch and is excluded from submission verification.
